# @kwitsch/claude-code-plugin-cli

Command-line tools for Claude Code plugin projects. It provides `claude-code-hook-types`, which writes and checks the TypeScript types of the `input` objects that `mcp_tool` hooks pass to MCP tools.

## Installation

```sh
pnpm add -D @kwitsch/claude-code-plugin-cli
```

Requires Node 26 or newer.

## Hook input types

A hook of type `mcp_tool` calls a tool of an MCP server with the object in its `input`. Set `hookTypes` in the hooks template to get a generated TypeScript file that describes that object for every server and tool, so the tool implementation can type its arguments:

```jsonc
// hooks.template.json
{
  "hookTypes": "src/hook-types.d.ts",
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Write|Edit",
        "hooks": [
          {
            "type": "mcp_tool",
            "server": "plugin:my-plugin:checker",
            "tool": "check_path",
            "input": { "path": "${tool_input.file_path}", "strict": true }
          }
        ]
      }
    ],
    "PostToolUse": [
      {
        "matcher": "Write",
        "hooks": [
          {
            "type": "mcp_tool",
            "server": "plugin:my-plugin:checker",
            "tool": "check_path",
            "input": { "path": "${tool_input.file_path}", "tags": ["post", 1] }
          }
        ]
      }
    ]
  }
}
```

- `hookTypes` is a path relative to the hooks template's directory and ends in `.ts`, `.mts` or `.d.ts`; anything else is `template-invalid`. It is never copied to `hooks/hooks.json`.
- With `hookTypes` set, every `mcp_tool` hook needs a non-empty string `server`, a non-empty string `tool` and an object `input`; otherwise the build fails with `hook-input-invalid`. Without `hookTypes`, `mcp_tool` hooks are copied unchanged.
- Types are inferred from the JSON literals: a plain string, number, boolean or `null` becomes its literal type, a string containing `${...}` becomes `string`, an array becomes a tuple and an object lists its keys sorted. Hooks that call the same server and tool with different shapes produce a union.

The template above generates:

<!-- dprint-ignore -->
```ts
// Generated by claude-code-hook-types from the hooks template. Do not edit.
export interface McpToolHookInputs {
  "plugin:my-plugin:checker": {
    "check_path": { "path": string; "strict": true } | { "path": string; "tags": ["post", 1] };
  };
}
```

Use it in the tool implementation:

```ts
import type { McpToolHookInputs } from "./hook-types.js";

type CheckPathInput =
  McpToolHookInputs["plugin:my-plugin:checker"]["check_path"];

export function checkPath(input: CheckPathInput): boolean {
  return "strict" in input ? input.strict : input.tags.length > 0;
}
```

The build never writes this file: [`@kwitsch/tsdown-preset-claude-code`](https://github.com/kwitsch/rolldown-plugin-claude-code/tree/main/packages/tsdown-preset#readme) and [`@kwitsch/rolldown-plugin-claude-code`](https://github.com/kwitsch/rolldown-plugin-claude-code/tree/main/packages/rolldown-plugin#readme) fail with `hook-types-stale` when the file is missing or differs from what the template generates. Write it with the CLI.

## Usage

```sh
claude-code-hook-types [--check] [template]
```

- `template` is the hooks template, `hooks.template.json` by default.
- Without `--check`, the command writes the file named by `hookTypes` (relative to the template, and it must stay inside the template's directory) and prints `wrote "<file>"` or `"<file>" is up to date`.
- With `--check`, it writes nothing and exits with code 1 when the file is missing or stale; run it in CI.
- Problems of the template are printed as `<severity> <code>: <message>`. Only problems that prevent generating the types make the command fail; other template errors are listed and the file is still written.

Run it before type checking and building:

```jsonc
// package.json
{
  "scripts": {
    "pretypecheck": "claude-code-hook-types",
    "prebuild": "claude-code-hook-types"
  }
}
```

```sh
pnpm exec claude-code-hook-types --check hooks.template.json
```

The generated file has one fixed layout, so exclude it from your formatter (for dprint, add it to `excludes`).

Releases are published from GitHub Actions with npm provenance: the package page on npmjs links the commit and the workflow run that built each version.
